# 自注意力情感判断器 · Attention-Sentiment

用一份**纯手写的 `SelfAttention`**，从零搭一个能判断中文句子情感倾向的小模型。输入一句话，输出「正面 / 负面 + 置信度」，并告诉你**是哪几个字在支撑这个结论**。

没有用 `nn.MultiheadAttention`，没有加载预训练权重，全部 527 行代码，含数据生成、训练、推理、可解释性归因。

```
输入：虽然贵但是真的好用
判断：正面    置信度 100.0%

  『哪些字在支撑「正面」这个判断』
    好  ▲ ■■■■■■■■■■■■■■ +1.00  支撑
    用  ▲ ■■■■           +0.33  支撑
    真  ▲ ■■             +0.19  支撑
    的  · ■              +0.11  无关
```

## 为什么做这个

学 Transformer 的时候，最容易卡住的地方不是公式，而是**「我怎么知道自己写对了」**。

网上的自注意力实现大多是贴一段代码就结束，形状对得上就当作正确。但形状对不代表语义对：`mask` 广播错了会静默算出错误的矩阵，`√d_k` 忘了除训练照样能跑，注意力权重看起来像模像样其实全部塌缩到一个标点上。

所以这个仓库做两件事：

1. **`verify.py`** —— 用 5 个可证伪的实验，证明那份 6 行的 `SelfAttention` 逻辑是对的；
2. **`sentiment.py`** —— 把它训练成一个真能干活的模型，因为「能判对句子」比「形状是 `[1,4,4]`」有说服力得多。

## 模型结构

```
输入 text: "这个产品太差了"
   │
   ├─ 字级切分        →  [这, 个, 产, 品, 太, 差, 了]
   ├─ 查表 Embedding  →  [7, 40, 64]          每个字 64 维
   ├─ 加位置编码      →  [7, 40, 64]          可学习，最长 40
   │
   ├─ Transformer Block × 2
   │    ├─ LayerNorm
   │    ├─ SelfAttention (单头, d=64)          ← 手写的核心
   │    ├─ 残差相加
   │    ├─ LayerNorm
   │    ├─ FFN: 64 → 128 → 64 (GELU)
   │    └─ 残差相加
   │
   ├─ LayerNorm
   ├─ 掩码平均池化    →  [40]                  PAD 位置权重为 0
   └─ Linear(64→2)   →  正面 / 负面
```

**参数量 72.5K**，其中约 9.5K 是 Embedding 和位置编码，主体在两层 Block。

核心的自注意力只有 6 行（`self_attention.py`）：

```python
Q, K, V = self.Wq(x), self.Wk(x), self.Wv(x)
attn_score = torch.matmul(Q, K.transpose(-2, -1))      # 点积求相似度
attn_score = attn_score / (Q.size(-1) ** 0.5)          # 缩放，防数值爆炸
attn_weight = F.softmax(attn_score, dim=-1)            # 归一化成权重
out = torch.matmul(attn_weight, V)                     # 加权求和
```

训练版额外支持 `mask`，用于屏蔽 PAD 位置：

```python
if mask is not None:
    score = score.masked_fill(~mask.unsqueeze(1), float("-inf"))
```

## 训练细节

### 数据：模板合成 + 规则打标签

没有现成标注数据，用组合生成造了约 **1.06 万条**带标签的句子：

```python
POS_WORDS = ["好","棒","满意","推荐","划算","好用",...]   # 30 个褒义
NEG_WORDS = ["差","糟","失望","贵","难用","卡顿",...]     # 26 个贬义
DEGREE    = ["", "很", "非常", "太", "有点", ...]         # 程度副词
NEGATION  = ["不", "没", "不怎么", "不太", "一点也不"]     # 否定词
SUBJECTS  = ["这个产品", "这家店", "物流", ...]           # 19 个主语

label = 1 if 褒义词 else 0
if 出现否定词: label = 1 - label        # 否定翻转极性
```

标签由规则算出，不需要人工标注。为了让模型学到**语言规律而非词表**，刻意加入了三种结构：

| 结构 | 占比 | 例子 | 学到什么 |
|---|---|---|---|
| 否定句 | 35% | 这个产品**不太**差 | 「不」作用于哪个词 |
| 转折句 | 30% | **虽然**贵**但是**真的好用 | 结论看后半句 |
| 无主语短句 | 30% | 不太好用 | 不依赖固定句式 |

后两种是**看了错误案例反推补上的**（见[踩坑记录](#三个踩过的坑)）。

### 超参数

```python
bs      = 128          # batch size
lr      = 4e-3         # AdamW 峰值学习率，weight_decay=0.01
epochs  = 32           # 82 步/epoch，共 2624 步
sched   = OneCycleLR   # 先升后降，比固定 lr 收敛快
loss    = CrossEntropy
clip    = 1.0          # 梯度裁剪
```


## 三个踩过的坑

### 1. `mask` 少一个维度，会静默算错

```python
# 错误：mask [B, L] → [B, 1, 1, L]，和 [B, L, L] 广播成 [B, B, L, L]
score.masked_fill(~mask[:, None, None, :], float("-inf"))

# 正确
score.masked_fill(~mask.unsqueeze(1), float("-inf"))
```

错误版本会让张量凭空多一维，直到残差相加时才报形状不匹配。更麻烦的情况是形状恰好对上——那就永远发现不了。

### 2. 注意力权重不能直接当「解释」

训练完打印注意力矩阵，发现每一行都有 **0.99 的权重指向「的」这一个字**，列占比 66%。这不是模型学到了「的字很重要」，而是 **attention sink**：小模型倾向于把所有信息丢进一个「垃圾桶」token，因为那里不需要被关注。

所以如果拿注意力权重做关键词高亮，高亮的永远是「的」。这个仓库改用了**遮挡法**：

```python
# 把第 i 个字替换成 <unk>，看正负类的 logit 差距缩小了多少
for i in range(len(ids)):
    probe = list(ids); probe[i] = Vocab.UNK
    contrib[i] = base_margin - margin(probe)
```

两个细节都是踩出来的：

- **用 logit 差值，不用概率**。置信度饱和在 100% 时，删字概率也不动，遮挡法完全失效。
- **替换，不删除**。删字会改变序列长度，位置编码整体偏移，归因结果被污染。

### 3. 数据缺什么，模型就错什么

第一版模型把「**不太好用**」判成正面。查原因：训练数据每句都以主语开头，模型学会了认句子结构，遇到 4 个字的光秃秃短句就失灵 → 补 30% 无主语样本。

第二版把「**虽然贵但是真的好用**」判成负面。原因：训练数据全是单句，没有转折句，模型不知道「但是」后面的话更算数 → 补 30% 转折模板。

两次都是**先看错例、再补数据**，不是一开始就设计好的。

## 已知局限

诚实地说，这是个**教学项目**，不是能上线的模型：

- **词表只有 172 个字**，超出字表的一律映射成 `<unk>`，生僻字基本无感。
- **二分类，没有「中性」**。输入「今天下雨了」这种无情感句，它也会强行选一边。
- **99.7% 的验证准确率不能当能力看**。验证集和训练集来自同一个生成器、同一分布，只是随机种子不同。遇到成语、反讽、口语化表达（如「质量没话说」）就会错。
- **train 收敛到 1.000 而 val 停在 0.997**，说明模型已经把 1 万条数据背下来了，合成数据上很常见。
